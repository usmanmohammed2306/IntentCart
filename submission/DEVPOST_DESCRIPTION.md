# IntentCart

**A shopping agent should know when a plan works—and when it needs to stop.**

## Inspiration

The dock looks perfect. The monitor is a bargain. The cables fit the budget. Then everything arrives, and the setup cannot do what you bought it to do.

Buying a workstation is a systems problem disguised as a shopping list. The harder question comes when an AI agent can spend: which facts support its recommendation, what happens when they change, and did the user approve this exact basket?

IntentCart makes those questions visible, testable and connected to a real sandbox execution boundary.

## What it does

Describe a workstation, review the extracted settings, then explore a cinematic 3D setup. The finite planner checks the whole system: laptop transport, independent displays, resolution, refresh, charging, cable capacity and budget. Missing facts remain unknown. Conflicting variants remain conflicting. Targeted investigation gathers facts that can change a decision. If a component disappears, repair prioritizes changing the fewest component slots before price.

The studio follows **Describe → Explore → Review**. Orbit the setup, separate its components, follow their connections and inspect the evidence. A simple next-action guide keeps the task legible. Animation changes the view; it grants no authority.

The workbench adds explicit source review and expiry, owned equipment, exact variants, price uncertainty, preference comparisons and exports. Curated manufacturer specifications are manually reviewed records with explicit scenario allowances, not live prices or hardware certification. The workbench cannot create payments.

In Missions, review an owned, expiring quote and approve its exact fictional basket. Separately approve as the PayPal sandbox buyer. Capture and reconciliation check the order, quote reference, currency, amount and capture evidence. A changed plan requires fresh approval. On October 19, the complete USD 279 workstation basket was actually captured and fully refunded in the PayPal sandbox; separate provider reads verified the final order and refund. No goods, shipment or real-money purchase is involved.

## Where AI fits

An evidence agent can search, inspect, clarify driver permission, recommend a supported basket or defer. Deterministic local policies keep the project usable without credits. An optional Astropods Haiku 4.5 policy proposes the same bounded actions. Neither a fluent explanation nor a valid JSON object supplies product facts, changes budgets, grants permission or executes a payment.

Actual live validation used 17 model requests and USD 0.026906 in free Astropods credits. A native fixture completed four matched trials, two per controller; each controller repeated its supported decision. Three initial rejected requests and a harder-task overlength rejection remain in the evidence. That harder task finished one supported trial, one failed trial and two unattempted trials. This small diagnostic establishes an integration path and exposes failures; it does not establish model superiority or general reliability. No model GPU deployment or training was performed.

The retained Bayesian preference learner and CPU imitation experiments are inspectable, including negative findings. The learned acquisition student loses to stronger references on the supplied diagnostic average. Preference diagnostics show no regret improvement. These results stay visible because a useful engineering artifact should make its limits reproducible.

## Engineering evidence

Decision validity separates feasibility, bounded optimality, approval binding and execution knowledge. Dependency analysis shows why a changed observation matters. Failure replay runs actual local API routes against a separate durable fake-provider ledger, recreates interpreters after declared interruptions and reduces failures while preserving their violations.

An independent finite predicate matches the hardware validator on all 196,608 declared configurations. Ordered recovery, source-review, boundary, fictional-persona and local API matrices retain compressed traces, exact denominators, source identities and a coverage audit. Eleven deliberately injected faults are detected. These are software checks over authored conditions, not people or a public benchmark.

The retained acquisition comparison covers 384 fictional goals and 1,152 controller runs. Targeted inspection reaches all 73 feasible minimum-cost outcomes and correctly defers 311 infeasible goals, using 143 lookups versus a full census's 1,920. Stock-change repair matches 272 independent-oracle outcomes. These figures apply to that finite fixture, not real users, token savings or universal commerce.

## How it is built

Python, FastAPI, SQLite, NumPy, local JavaScript/WebGL with Three.js, finite constraint solving, source-bound reports, strict JSON tools and PayPal Orders v2 sandbox execution. Local durable request/cost reservations retain failures and do not automatically retry uncertain responses. Pinned dependencies, offline verification and clean source packaging keep the free core runnable after trial credits expire.

PayPal, actual Astropods gateway inference, historical Channel3 discovery and an executed local Postman/Newman walkthrough have distinct evidence. Other sponsor resources are documented without pretending they were used. Cash spending remains USD 0.

## What remains

The application is a single-instance sandbox project. A consented human pilot has not occurred; fictional personas are labeled synthetic. Real-money settlement, distributed operation, live inventory and fulfillment are outside this release. Public source/video URLs, remote CI and final entry are completed by the entrant. Current commands, artifacts, failures and limits are in the source and submission kit.
